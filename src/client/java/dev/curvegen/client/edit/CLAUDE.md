# In-world editor

## Shape contract

- `EditShape` uses coordinates in the shape's own axes measured in blocks from its unpadded minimum corner. `Content` uses world-axis offsets from the box origin for placement. A failed solve supplies empty block and carve lists and a player-facing error. Read the realized dimensions through `size` after a resize. Moves, bumps, and fitting report any shift of the minimum corner so unchanged points stay fixed in the world. A null result from `bump` delegates the resize to the editor.
- Control points are listed in row order for a surface. The alternate gesture edits columns. Duplicating a curve point moves the copy half a block towards the next. A shape can supply a ray hit as own x, y, z followed by distance from and along the ray. Otherwise the editor finds the closest spot on the displayed curve.
- A 2D shape uses x for drawing right, y for drawing up, and z for depth. Tipping switches floor mode. When a tipped 3D hologram becomes a 2D drawing, pick two horizontal directions even if the old x or z pointed vertically. A 2D solve may finish after floor mode changes. Assemble those blocks in the mode and dimensions of the result. A 3D solve settles states in world orientation, so turning it requires another solve.
- Keep `curve` and `options` cheap because the editor and radial menu call them every frame. The last 3D equation solve traces its wireframe on the worker. Stretch the wireframe to the live box while the next result is pending. Shape options use the radial menu's wedge limit, including Back. The editor supplies point actions for curves and surfaces supply row and column controls.

## Editing and background work

- Apply each drag from its starting snapshot. Preserve the initial ray-to-handle offset so the handle does not jump. Face handles move along an axis. Plane drags that allow scrolling move the plane in whole blocks. Base handle thinning on the starting box during a drag. Consume stray clicks during a drag, and consume releases for presses taken from the game. End a drag before recording another edit so the next frame cannot restore its old settings.
- Keep the rotation pivot across quarter turns and clear it when the box is refitted. Consecutive `Editor.edit` calls sharing a non-null group can share one undo entry, such as wheel steps. Record screen changes as one edit when it closes, rebasing when the editor records its own changes. Undo restores shape settings and derives connection behavior again from the current block choices.
- Solve on the worker using private settings and no access to Minecraft or live settings. The 2D equation solver can resolve its locked height in that copy. Keep a separate copy to compare against a pending or shown solve. Build blocks on the client thread. Discard results when switching between 2D and 3D. Refit the box when a result resolves dimensions. Pending blocks retain their solve origin, adjusted for subsequent translations.
- Keep the last blocks visible while solving or repainting. Replace changes placement only. Switching Carve on needs another solve for shapes that compute the clear set only on request. Paint retains the block choices and matcher version it was built with. Unpainted blocks can take current choices when they are built. Export from a screen must check for pending settings before writing its hologram.
- Cancel superseded solves during quick edits. The starvation interval lets a solve finish during a continuous drag. The slow threshold still permits dropping work that would show outdated blocks.
- Keyboard clicks include repeats, so `StepHold` takes fresh in-world presses from raw key events and uses clicks for mouse bindings. A tap acts immediately. On typed input, retract the tap's edit if it is still newest. If other edits followed it, credit its one block towards the typed amount. Undo and redo cancel the hold.

## Drawing and capture

- The collector draws submitted geometry later in the frame. Keep its inputs scoped to the frame that submitted it. Use box-relative coordinates to preserve precision far from the world origin. Draw lines as strips facing the camera with screen-space width. Clip before the camera plane to prevent strips from crossing it and filling the view. The game's fogged line types can hide far edges while handles remain visible.
- Reuse the solved geometry and refresh placement eligibility against the world. Collect carve operations before placements so placements win if they share a position. Skip faces hidden by full neighbours and share empty face buffers when the block limit suppresses drawing. Use only camera-facing faces to avoid blending each box twice. Expand carve boxes and capture outlines slightly to keep them visible against the blocks.
- Submit geometry on the far side of the water surface before translucent terrain, then geometry on the camera's side after it. Use the collector's regular phase if it has no after-terrain storage. Handles draw with dim through-wall geometry and a depth-tested pass.
- Keep the aimed handle when entering the radial menu so Remove point still has a target after the cursor is freed. Capture takes priority over editor HUD hints, and screens have their own overlays. Keep error and progress lines visible with shape information disabled.
- Capture uses only right clicks so a hologram keeps its other controls. Flatten and check the capture dimensions in the view at the second corner. Once naming opens, the dialog receives the release. Cancelling naming lets the player choose the second corner again.
