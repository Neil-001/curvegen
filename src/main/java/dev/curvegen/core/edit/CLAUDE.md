# Editor geometry and input

## Boxes and orientation

- `Box` uses whole world blocks and an exclusive upper edge. Spawn centres the box laterally on the anchor using integer half sizes and puts its bottom at the anchor's y. Keep the original doubled x and z centre across turns. A turn that swaps odd and even sizes must round, and recomputing the pivot after rounding would move the box after four turns.
- Each of the 26 resize handles has one sign per world axis. One, two or three nonzero signs select a face, an edge or a corner. Thin axes lose their crowded outer layers but keep the two face handles so every axis stays resizable. A regular drag anchors the opposite face. A symmetric drag grows in pairs and keeps the centre and size parity, stopping at one or two blocks. `dragSize` accepts NaN for an unused target coordinate. When a lock resizes an undragged axis, keep its lateral centre or its vertical bottom.
- `Orient` uses Minecraft's direction numbers without importing Minecraft. Facing a player forward puts own x to their right, y up and z away. A turn is clockwise from above. A tip moves the top away from the player. Points and cells are offsets from their respective box minima. On a reversed axis, a point maps to size minus coordinate and a cell maps to size minus one minus index. The cell transform also works outside the box.
- Solve `Turned` shapes in world axes so the solver can choose states in their final orientation. Remap each block's 125 lattice samples between world and own order for both `lattice` and `follows` to preserve the shape's sampling and interpolation rules. A `uniform` run describes consecutive cells along own +x unless the shape explicitly supplies the same bound in all directions. Reuse the full run when that guarantee applies or own +x points east. Any other direction gets just the current cell's classification.

## Shape edits

- A 2D drawing measures x across, y up and z through its depth from the front bottom-left corner. Control handles and ideal curve segments sit halfway through the depth. Both editors pass segments as packed start and end XYZ triples. The 2D equation gets its trace from the solver. `Edit2D.overlay` takes its packed XY segments, subtracts the solver's grid margin and scales them from the solved box to the current box while it waits for a new solve. `Edit3D.curve` can draw the curve or nine lines each way across a surface from live settings during a drag.
- Keep locked equation dimensions consistent with the solver. For a 2D equation the width sets the scale if both dimensions move, and a height-only drag derives a new width. For a 3D equation the first dragged own axis sets the scale, with equation x, z and y supplying width, height and depth respectively. Keep equation ranges fixed as the box stretches. An inequality supplies its own filled side, so disable the fill or thickness controls it makes inapplicable.
- Torus handles change the stretched box while ring and tube settings keep the hole's proportions. Editing either setting scales the affected box dimensions by the same factor to preserve their stretch. The tube fits within the ring diameter, including when the ring shrinks.
- Control points stretch with the box. An outward drag can grow the box by whole blocks, with half-block coordinates when Snap is on. `movePoint`, `bumpPoints` and `Edit3D.fit` return the displacement of the minimum corner in own axes, with nonpositive components. Feed that shift to `Box.regrown` so the editor preserves the world position of the unaffected geometry. `bumpPoints` and `Edit3D.fit` return null when they have no control points to edit. A bump anchors the opposite bound and stretches the points together. Limit the stretch before scaling so size limits preserve proportions. Shrinking stops at one block or the existing span if it is smaller. A shape with no extent along that axis uses the ordinary box bump. Refitting after surface degree reduction tolerates up to one billionth of a block around integer boundaries to avoid growing the box from arithmetic roundoff. Direct drags use the actual target. Apply the ray intersection displacement to the original own-axis control point so a stationary ray or an unchanged axis preserves its coordinate.
- A 2D Bézier insertion puts a new control point at the picked spot in the order of the nearest curve parameter and preserves the endpoints. A 3D insertion raises the degree and preserves the curve or surface. Curve duplication offsets a control point by half a block towards its next neighbour, or towards its previous neighbour at the end, and inserts it between them. A surface edits a whole row by default and a whole column with Alt. Its `columns` count is zero for curves so callers can distinguish their single line. Degree reduction approximates the surface and can move remaining control points beyond the box, so refit after removal. The point insertion methods return the selected control index or -1 when insertion is unavailable.

## Picking and key holds

- `HandleMath` takes points and rays in one shared frame for both the editor and the preview. Near-parallel drags reject intersections to avoid large jumps. `alongAxis` gives an axis coordinate or NaN, and `onPlane` gives a point or null if the ray goes the wrong way, exceeds reach or is too close to parallel. Ray distances start at the ray origin. For a point behind it, the origin is the nearest point on the ray. `nearestOnSegments` returns position, distance from the ray, distance along it and segment index. `Edit3D.lookAt` returns the same first five values for a curve or surface.
- Match in-world pick radii to the rendered handle size as distance grows. Score candidates by the fraction of the radius they miss the crosshair. Exclude handles at or behind the ray origin and give nearer handles a small preference when they nearly overlap. In the menu preview, test against the square around a point and use depth only to break equal cursor distances.
- `Orbit` projects orthographically so blocks keep their apparent size and a point stays under the mouse throughout a drag. Angles are radians and scale is pixels per block. At zero yaw the camera looks north from the south, positive yaw moves it east, and positive pitch lifts it. Screen y increases downwards. Projected depth is zero at the target and grows away from the camera. Unprojection uses that same depth, drag keeps the starting depth, and zoom anchors the point under the cursor. Dragging right brings the left side of the shape around.
- Feed `HoldTimer.press` from fresh in-world key-down events. Minecraft also queues clicks for repeats, which can continue after a screen closes over a held key. `takePress` consumes the press events for the next tick and prefers a fresh press of another key over the current one. Every fresh press starts its own hold and emits `STEP`, including a release and press between ticks. An eligible hold shows progress after a delay and emits `OPEN` after the full interval. Progress is a fraction from 0 to 1, or -1 while the bar is hidden. Handle the open before calling `opened` if the caller needs the key. Cancel the hold on undo or redo because the number box would replace an edit that is no longer the latest one.

## Radial menu

- Shapes supply live `Option` getters and setters. Setters change the setting and the editor handles undo and box fitting. `off` supplies the disabled tooltip's translation key or null. Budget 72 pixels for fixed wedge labels. Text validation returns a diagnostic or null. Selecting a number opens its input box and scrolling steps it. Grid stepping moves to the next multiple in the requested direction, with a tolerance for floating-point drift at grid points. Wrapped whole numbers include both end values. Shape dimensions are edited through the box and equation ranges through the full screen.
- Paint keeps its pattern controls in fixed slots under Off, Pattern and Mix so players can find them even when disabled. The client inserts Choose in the second slot. Without Chroma Studio, omit Gradient from the source cycle unless the current selection is already Gradient, since the cycle cannot disable one entry and still needs to represent the saved selection. A shape without wrapping uses projection directions and shows the one it actually paints with, even if the stored gradient direction wrapped.
- Wedge zero points up and indices advance clockwise. Place the labels outside an ellipse sized to leave room at the screen edges. Use its proportions to pick slices in both ring styles so each wedge points at its label. Only the stretched ring applies those proportions to the dead zone. The round ring leaves boundary pixels empty when their corners disagree on a wedge. The stretched ring uses pixel centres and a narrow gap. Preserve its original half-pixel cursor offset on odd screens. The round ring picks from the same integer centre used for drawing. The ring and labels fit twelve wedges at 427 by 240 and reserve room below for two lines of text.
- Persist both top-level orders with one list. `presets` is their only shared ID, so all entries on either side of it can be combined without reordering either menu. An empty list represents the defaults. Ignore unknown and duplicate saved IDs. Put an unsaved wedge after its predecessor from the default order to keep related actions together in a player's custom layout.
