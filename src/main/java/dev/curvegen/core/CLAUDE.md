# Core geometry

## Fields, coordinates and painting

- A `Shape3` supplies its grid size, scalar field and wireframe. Field coordinates use blocks from the low corner of the padded grid, with x east, y up and z south. The solid band includes both endpoints. Use signed distance and a band for a shell so the solver can interpolate through a thin wall without a crease. `carve()` supplies a separate open interval tested at block centres.
- The default `uniform` bounds a run along +x using the field at the cell centre and half the block diagonal. It requires a field that changes by at most one per block. A positive run is solid, a negative run is empty and zero requests sampling. `lattice` writes a 5×5×5 grid at quarter-block intervals, x fastest, then z, then y. Use `inset` for jumps on block faces so a cell samples its own side. Disable interpolation with `smooth` for the whole shape or `follows` for an individual cell. Direct sampling evaluates all 4096 voxel centres.
- The wireframe uses one xyz array per polyline, in draw order. A curve supplies its own line before its control polygon. A patch puts its surface lines before the control grid. An equation puts the box before the section contours.
- `Wrapping.place` writes distance along and across a shape to the first two output entries. Mark closed axes so paint can repeat across their seams. Map through the nearest point to keep a pattern aligned through a thick wall. The editor's axes point right, up and away from the viewer. Choose the axes so a pattern reads normally from the outside. The painter caches the mapping per solve and can call it from multiple threads. A null mapping leaves projection available.
- `Target` uses 2D grid coordinates with y up. It stores a separate centre line and width for wrapping strokes. For a filled equation, plot edges use the same crossing interpolation and sample order as the contour, so wrapping can join the two exactly. Paint subtracts the grid padding to address the shape's box. `Layout` trims the built cells and gives carve cells the same origin, even outside the new bounds. Each built cell retains the original grid index for paint and the piece above for placement.

## Solving and placement states

- In 2D, `Pieces` stores 16×16 silhouettes with row zero at the bottom, and `EDGE` and `STURDY` order their faces bottom, top, left, right. Edge coverage controls whether a block is hidden. Sturdiness controls attachment. Flat shapes choose pieces by their top profile and upright shapes by their side profile. Both orientations share the line pieces. Chains and end rods default off so a normal solve doesn't pick them for thin lines by default.
- The 2D solver's upright refinement includes both side neighbours and the three cells in the row below because that row's walls can depend on connectors above. Its flat refinement needs the four adjacent cells. A wall post inherited from higher in the column is applied after refinement to keep the scoring dependencies local. Deep drawings show the front layer, where the wall connects to the next layer on only one side. Chains and rods cover the wall's centre without covering its side strips. A chain or rod can win a tie with air to keep half-block strokes continuous. Air cannot win the reverse tie, so equal-cost picks of that kind cannot cycle.
- `Pieces3` keeps finished states in shorts and numbers its directions north, east, south, west, down, up. `props` uses Minecraft property names so placement can build the state without guessing. Stair facings point toward their tall backs, trapdoors and shelves put the panel opposite the facing, and rods face away from their plates.
- `Pieces3.PARTS` decomposes each state into disjoint volumes, so `Solver3` scores each part once per cell and sums the relevant overlaps. Walls split the footprint into the centre, four post strips, one part for the four post corners and four outer arms, with each part split at the low-wall height. Keep the visible boxes separate from wall coverage. The fence's two bars score as drawn, but its collision arms cover the full strip at the bottom. Fences join fences. Panes and walls join each other.
- `Solver3` samples only the unique octant of a symmetric field, scores the x/z quarter, and reflects tokens rather than finished states. Gravity makes a wall's state depend on the block above even if the field mirrors in y. Sampling takes strips of rows to spread work on flat shapes over the common pool and joins the strips in grid order. Sample the 5×5×5 lattice as needed and score at 16³ voxel centres. Settings must be a snapshot and the cancel supplier must be thread-safe.
- A 3D token represents the fixed part of the piece. Straight stairs and the base fence, pane and wall-post tokens acquire their final state from neighbours. `Run.gather` reaches two steps in the same plane because a connector can depend on a stair shaped by another stair. It also reaches down through wall columns. Wall states use a token-change stamp to avoid recalculating the same column for each cell. Check cancellation at each pick because one tall column can make a pick expensive.
- Test hidden blocks before applying a shape's cut so a cut doesn't leave a cap. Sparse settling expects a settled source and recomputes the same dependency region as refinement. Dense settling can start from a token grid. When changing either path, preserve their equality on settled input and preserve the original solve's error, volume and sweep count when only settling holes.
- `Settle2D` uses x east for columns, then y up and z south for upright rows and layers. For flat shapes, rows run north and layers stack up. It exposes connections in drawing-relative order using two bits per side and a separate post bit. Keep its token conversion aligned with `BlockChoices.stateFor`. For sparse holes, settle the intact shape first. Two layers at each face and one middle layer cover an upright extrusion. For a floor, reuse the lowest layer only after adjacent lower layers agree, since only walls transmit state down through the stack.

## Algorithms for the 3D shapes

- Ellipsoid distance finds the largest root of the nearest-point equation using Newton steps from the left. On a symmetry plane a zero coordinate drops a term, but the closest point can be off the plane. In that case clamp to the dropped pole and recover the missing coordinate from the ellipsoid equation. For solids, an implicit field scaled by the shortest semi-axis gives the same zero set and meets the default slope bound. For shells, use true distance for thickness. The torus also scales its unstretched distance by its smallest scale. On small shapes, a crease in the field can reach the interpolated surface, so use direct samples there. Ellipsoid wrapping uses longitude from the back and latitude from the bottom. Torus wrapping starts under the tube and runs up its outside.
- An equation maps math x east, y north and z up to preserve handedness. Its typed inequality overrides the fill setting. Surface mode follows the gradient in bounded steps and measures distance back from the root. A larger finite difference can find a nearby root where the local slope vanishes. Reject sign changes at jumps and poles unless values converge to zero. Use the sign of the approach to distinguish the two sides of a tangent root for interpolation. In `uniform`, corners and centre estimate which cells are safe to skip. The fast path for distant cells also checks that the corners follow the local linear estimate. When all nine points are undefined, check the full lattice before skipping.
- A tube uses a subdivided centre line. Subdivision tests the midpoint and quarter points against the chord as well as its length. For open hollow tubes, extend both ends along tangents from the first distinct control points and cut blocks strictly nearer the extensions. This makes the ends follow block boundaries and keeps centres level with the ends. The wireframe and wrapping use the actual curve segments. Wrapping projects the previous seam to the new cross-section plane, then rotates all seams together as close to down as possible, weighted by segment length.
- A patch uses a signed distance to a local quadratic approximation of the surface. Beyond an edge, a small extension compensates for the loss of any voxel adjacent to a NaN sample. For proximity queries, index alternating samples including the outer edge and walk to closer neighbours. A fold can have a closer sheet far away in grid coordinates, so test other nearby sheets as well. Within a block, seed each lattice query from the adjacent query only when the corners and centre agree that a single sheet is near. The patch's wrapping axes run along the grid's columns and rows, with lengths averaged across the patch. Pick the side facing the player or up so the pattern reads from that side.
- `Near3` keys candidates by bucket. The triangle inequality rules out any candidate farther from the bucket centre than the closest candidate by more than the bucket diagonal. Beyond the requested reach, a bucket may omit the true nearest item. Queries outside the grid use the nearest bucket. A bucket's array has spare capacity, so iterate only its count.
- Degree changes in `Bezier3` use row-major control points, with u along a row and v between rows. Moving one control point changes the curve or patch. Insertion preserves the shape by elevating the degree and then selects an interior handle. Reduction fixes the ends and fits the elevated control points by least squares. The normal matrix is positive definite and tridiagonal, so elimination needs no pivoting. Reducing a patch row fits every column and preserves the two end rows.
- Ray queries use the control points' coordinates. The curve answer is `{u, x, y, z, distance from ray, distance along ray}`. The patch inserts v after u. Curve picking refines the closest sampled chord on the actual curve and checks its seed separately because a self-crossing curve can have more than one local minimum. Patch picking finds the first mesh hit, retries on finer meshes near it to recover close crossings, then uses Newton steps on the patch. A near miss within 0.05 blocks can count as a hit so the mesh approximation doesn't lose a ray that grazes a hump. Give triangles a small overlapping tolerance to avoid misses at their shared edges.

## Preview and data contracts

- `Mesh3` groups rectangles by normal so the camera can skip three directions at once. Each face stores its two in-plane spans and the coordinate along the normal, in blocks. Drop a boundary rectangle when its neighbour fills the shared face. Paint uses the face's occupied-block index in grid order with air omitted. `Raster3` reuses the inverse screen transform for every face with the same normal. Grid lines disappear below five pixels per block so they don't swamp the fill. Occluded wireframe pixels appear faintly once, even when several lines overlap.
- `Silhouette` works on top-down pixel rows and counts diagonal neighbours so a stair's inside corner is outlined. Its rectangles cover exactly the same pixels for the Count icons. `Count3` groups states by the builder-facing shape and chooses the smallest south projection for the icon so a stair shows its profile.
- `Expr` returns left minus right and retains the relation for choosing the filled side. Bare 2D expressions define y and bare 3D expressions define z. Implicit products share the precedence of explicit multiplication and division. Unparenthesized function arguments take adjacent factors as in Desmos, and negative bases admit real roots when the exponent resolves to a fraction with a small odd denominator. Range diagnostics carry a translatable field label.
- Use `ShapeSettings.copy` when passing live settings to workers or storing editor undo. Clone the point arrays and include new settings in both `set` and `same`. Keep translated diagnostics as `Message` values until the caller renders them.
- `PresetData` stores one tab's settings as text and can store block IDs and toggles separately. Orientation and extrusion depth belong to the build. Encode control points as semicolon-separated points of comma-separated coordinates. A surface needs its dimensions and complete grid together. Presets without a curve's hollow flag describe solid curves. Older complete block lists imply shelves, chains and rods were disabled if they predate those families.
- Litematica packs palette indices using at least two bits each into a contiguous bit stream. An index may cross a long boundary. `LastPlacement` stores one placement. Redo yields the old placement to the caller, which records it again after restoring it.
- `CommandReplies` uses a position match for successes and send order for errors because vanilla feedback has no command ID. Display ambiguous replies, and resume hiding errors after a matching own success restores the order. Keep an identifiable nested `run setblock` in the queue until activity times out because the command can emit multiple replies. Earlier queued commands can still match. Server-side functions can issue commands the client cannot identify from the outgoing text. Preserve the first occurrence of an actionable error and match the syntax-context line to the preceding error.
