# Core tests

- Use `Shapes3Cases` for common 3D fixtures. Intersecting sheets under a slope exercise mixed wall heights and posts, posts with rails exercise thin connectors, and the stepped pyramid with a pit exercises both stair corner types. The lattice fixture makes aligned holes through every layer, like a pattern on a face. Also test scattered holes and repeat settling after a previous cut.
- `Rules3Test` and `ConnectionRulesTest` derive connections and wall coverage from finished states and geometry independently of solver lookup tables. Keep that independence. For sparse settling, compare both `Solver3` and `Settle2D` with a complete settle and assert that some neighbours really changed. `ConnectionRulesTest` uses smaller ellipses in the layer-hole sweep because the larger cases exercise the same connection rules and cost most of its runtime.
- Uniform-run tests walk every cell in each nonzero run. Keep fixtures that exercise fields steeper than the default bound, jump discontinuities, asymptotes and narrow domain edges. Exercise folded or sub-block-thick patches with both seeded and independent lattice queries. Rotating a shape must preserve its sampling behaviour and volume. Its block selection can depend on which way is up.
- Cancellation tests cover interruption during a single sampled layer, between refinement picks in tall wall columns and during sparse settling below a hole. Keep numerical regression assertions unchanged unless the intended build changes.
- `SilhouetteTest` keeps the four-neighbour baseline to show which profiles change when diagonal neighbours count. Compare the rectangle form with the pixel form for every piece. `Preview3Test` checks face ownership with air omitted and compares family colouring with per-block colouring. Test line overlap behind the shape so repeated drawing cannot brighten hidden lines.
- `ShapeSettingsTest` mutates every setting to catch gaps in undo snapshots. The separate `PaintTest` covers individual paint fields.
- For timings, temporarily remove `@Disabled` from `Shapes3Timing` or `Preview3Timing` and run `./gradlew :fabric:test --tests '*Shapes3Timing*' -i` or `./gradlew :fabric:test --tests '*Preview3Timing*' -i`. The preview timing uses a 259×144 menu picture at GUI scale 3, first fitted and then zoomed five times. Compare face generation and draw time separately because faces are reused as the camera moves.
